# Лабораторный практикум: Разработка системы данных

## Описание проекта
Цикл лабораторных работ по созданию комплексной системы управления данными для торгового предприятия. Проект включает разработку базы данных филиалов, центрального хранилища данных и аналитической витрины.

## Выполненные работы

### 1. Разработка базы данных филиалов
Создана реляционная база данных для управления информацией о продажах в филиалах торговой сети.

**Реализованные сущности:**
- **Покупатели** - учет клиентов филиалов
- **Товары** - каталог продукции с категоризацией
- **Категории** - система классификации товаров
- **Сделки** - учет продаж и транзакций

**Особенности реализации:**
- Связь "многие-ко-многим" между товарами и категориями
- Детализированный учет сделок с поддержкой сложных заказов
- Гибкая система ценообразования
- Уникальные идентификаторы и метки времени для всех записей

**Результат:**
- Разработаны две идентичные базы данных: "Филиал Запад" и "Филиал Восток"
- Наполнены тестовыми данными для проверки функциональности

### 2. Создание хранилища данных
Разработано центральное хранилище для консолидации информации из всех филиалов.

**Ключевые характеристики:**
- Оптимизированная схема для аналитических запросов
- Поддержка только операций добавления данных
- Исключение дублирования информации
- Масштабируемая архитектура

### 3. Разработка витрины данных
Создана специализированная витрина для недельной отчетности по продажам.

**Функциональность:**
- Агрегация данных по недельным периодам
- Быстрый доступ к консолидированным показателям
- Снижение нагрузки на основное хранилище

### 4. Автоматизация процессов
Реализована система автоматического наполнения хранилища данными из филиалов.

**Особенности решения:**
- Инкрементальное обновление данных
- Минимизация нагрузки на операционные системы
- Обработка данных из multiple источников
- Гарантия целостности и согласованности данных

## Техническая реализация
- Реляционная СУБД с поддержкой SQL
- Английские наименования объектов базы данных
- Стандартизированная структура таблиц
- Оптимизированные запросы и процедуры

## Лабораторная работа №5. Создание Процедуры наполнения Витрины данных.

Цель работы: разработать скрипт, или хранимую процедуру, которая обеспечит
наполнение Витрины данных на основании детальных данных, имеющихся в
Хранилище. Витрина данных наполняется данными за определенный период,
например за пять недель выбранных пользователем.

## Лабораторная работа №6. Создание скрипта восстановления утраченных филиалом данных на основании детальных данных Хранилища.

Цель работы: Создание скрипта, обеспечивающего обратный перенос очищенных
данных из Хранилища в выбранный Филиал.
Скрипт можно оформить как набор SQL команд, или как хранимую процедуру. Скрипт
должен переносить данные за выбранный промежуток времени из Хранилища в
Филиал. Скрипт должен работать исходя из того, что данные в Филиале полностью
отсутствуют.
сущность содержащую информацию о количестве купленного товара и цена. Сущность
Сделка будет содержать итоговую сумму покупки, а также дополнительную информацию,
например дату совершения сделки.
